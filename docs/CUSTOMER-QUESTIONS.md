# Customer questions, by trade

Every template is built to answer the questions a customer has *before* they contact or visit
the business. A template is not finished until each top question for its trade has an answer on
the site: a feature, a page or a line in `questions`. Use these lists in the intake call: the
client's answers become their `questions`, `visitInfo` and team filters.

How to read the tables: **Answered by** names the feature or field. "questions" means a line
in the `questions` list (home page and Plan your visit page).

## Every trade
| Question | Answered by |
|---|---|
| Are you open now? When do you close? | `visit` live hours; status in the header |
| Where are you, and where do I park? Is it free now? | `visit` address; `visitInfo.parking` (live free/paid status) |
| Can I get there by bus or train? How long from the station? When should I leave? | `visitInfo.journeys` (routes, Google Maps directions, leave-by helper) |
| Is it step-free / accessible? | `visitInfo.access`; questions |
| How much does it cost? | `price-list`, `price-page` |
| How do I book, and do I need to? | `booking` (Booksy, Fresha, WhatsApp, phone); questions |
| Can I pay by card? | `visitInfo.payment`; questions |
| Are they any good? | `reviews` (real Google reviews), `gallery` / `work` (Instagram) |
| What are your holiday hours? | `hours.exceptions`; `seasonal` banner |

## Adding a trade
Before building a new template, write its table in `docs/trades/<trade>/questions.md` with at least eight questions, and plan a
feature, page or `questions` line for each. The template's demo answers every one.

## Each trade
One file per trade, so trades built in parallel never edit the same lines. A new trade adds its own `docs/trades/<trade>/questions.md` (see "Adding a trade"); `npm run docs` lists it here.
